# qr-stream Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a React library plus demo PWA that moves a ≤250 KB JSON file between two devices with no network, using an animated sequence of fountain-coded QR codes.

**Architecture:** A DOM-free TypeScript core does compression, optional AES-GCM encryption, systematic Luby-Transform fountain coding, and a 20-byte binary packet format. A thin browser layer renders packets to canvas and drives the camera; React components and hooks wrap that layer. QR matrix generation and QR decoding are the only bought dependencies.

**Tech Stack:** TypeScript (strict), Vite lib mode, Vitest, React 19, `vite-plugin-pwa`, `zxing-wasm@3.1.6`, `qrcode-generator`.

**Spec:** `docs/superpowers/specs/2026-11-11-qr-stream-design.md` (design agreed in conversation; wire format below is authoritative)

## Global Constraints

- Node `>=22`, pnpm. No backend, no runtime network requests. Static build only.
- JSON input only, maximum `250 * 1024` bytes. Reject larger at file selection.
- ECC level `L` for every QR code. Never expose ECC as an option.
- All multi-byte wire fields are **big-endian**.
- Every QR frame is the **same pixel size**; payload is zero-padded to `blockSize`.
- `src/core/**` must not reference `window`, `document`, `navigator`, or `HTMLCanvasElement`.
- Passphrase is normalised with `normalize('NFKC').trim()` before use.
- `HEADER_SIZE = 16` (`magic(2) version(1) flags(1) sessionId(4) symbolIdx(2) K(2) blockSize(2) payloadLen(2)`); `FRAME_OVERHEAD = 20` (header + 4-byte CRC). `blockSize = qrCapacity(version) - FRAME_OVERHEAD`.
- `FLAG_GZIP = 1`, `FLAG_ENCRYPTED = 2`. Encode order is always **gzip → encrypt**; decode is **decrypt → gunzip**.

## Review Focus

1. **A stray QR code in the room** (poster, product label, another app's code). Expected: ignored silently, loop continues, no crash and no progress regression.
2. **Receiver starts mid-loop.** Expected: works from any `symbolIdx`, including repair symbols before any source block.
3. **Sender restarts with a new `sessionId` while the receiver is scanning.** Expected: receiver detects the change, does not deadlock on the abandoned session, and surfaces a switch prompt after a stall.
4. **Portrait-oriented camera frames.** Expected: `videoWidth`/`videoHeight` swap handled so the decoder receives correct dimensions and codes are not squashed.
5. **Degenerate sizes: 1-byte file and exactly 250 KiB.** Expected: `K = 1` single-block path works, and the 250 KiB cap boundary is accepted, not rejected.
